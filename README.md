# ORTO OrcaSlicer

**Текущая версия: `2.6.0-ORTO.18` — TEST**  
Тестовая версия ORTO Edition на базе OrcaSlicer 2.6.0. `2.6.0-ORTO.14` остаётся проверенной пользователем базовой версией STABLE TEST. Изменения `.15`–`.18` требуют проверки в Windows Portable.

## Статус версии

`2.6.0-ORTO.14` остаётся проверенной базовой версией **STABLE TEST**. `2.6.0-ORTO.15` убирает финальное модальное уведомление после подготовки оболочки. `2.6.0-ORTO.16` добавляет режим автоматической подготовки и нарезки через `--nogui`. `2.6.0-ORTO.17` исправляет инициализацию каталога данных в headless-режиме и обеспечивает наличие системных профилей для разрешения наследования. `2.6.0-ORTO.18` исправляет загрузку внешних пользовательских JSON-профилей с `inherits`: CLI теперь берёт настройки родительского системного профиля из загруженного bundle и накладывает на них значения внешнего JSON, как это делает GUI.

## Описание ORTO Edition

Релиз предназначен для интеграции с производственной системой ORTO и подготовки косметических оболочек протезов. Включает автоматизированное позиционирование модели, создание штатного Support Blocker, загрузку профилей принтера/процесса/филамента из JSON, графический режим и автоматический headless-сценарий подготовки с экспортом G-code.

Распространяется **только Windows Portable**. Установщик, MSI/MSIX и другие варианты установки в ORTO-дистрибутив не входят. Для работы используется отдельный каталог Portable-сборки, путь к которой задаётся в ORTO.

**ORTO OrcaSlicer** — специализированная сборка [OrcaSlicer](https://github.com/OrcaSlicer/OrcaSlicer), предназначенная для работы в составе производственной экосистемы **ORTO**.

Форк используется как специализированный инструмент подготовки косметических оболочек протезов. Основной сценарий — запуск слайсера управляющей системой ORTO, передача модели и профилей печати, автоматическая подготовка модели и экспорт G-code без участия оператора в режиме `--nogui`.

> Это не самостоятельная пользовательская редакция OrcaSlicer для повседневной работы. ORTO OrcaSlicer разрабатывается прежде всего для интеграции с ORTO.

Оригинальная документация базового проекта сохранена отдельно: [orcaslicer_readme.md](./orcaslicer_readme.md).

## Для чего нужен ORTO OrcaSlicer

Задача форка — встроить специализированную подготовку косметических оболочек непосредственно в производственный процесс ORTO, сохранив графический интерфейс, движок нарезки, систему профилей и возможности OrcaSlicer.

Ключевые принципы:

- запуск и управление рабочим сценарием со стороны ORTO;
- использование штатных профилей принтера, процесса и материала OrcaSlicer;
- автоматическое позиционирование подготовленной модели в рабочей области принтера;
- создание штатного модификатора **Support Blocker**;
- автоматическое позиционирование шва без необходимости ручной корректировки оператором.

## Подготовка косметической оболочки

При подготовке модели применяется следующая последовательность:

1. Модель поворачивается на **+90° вокруг оси X**.
2. Нижняя точка оболочки размещается над плоскостью стола на высоту, заданную в настройках ORTO. Значение по умолчанию — **3 мм**.
3. Создаётся вертикальный **Precise Seam Modifier**. Его центральная плоскость соответствует X=0 исходного STL с компенсацией центрирования геометрии при импорте.
4. Создаётся нативный объект типа **Support Blocker** средствами OrcaSlicer. Нижняя плоскость устанавливается на высоту, заданную настройкой ORTO (по умолчанию **20 мм**), а верхняя располагается ровно на **20 мм выше оболочки**.
5. Сцена обновляется после подготовки. Шов автоматически установлен в расчётное положение; дополнительных действий оператора с ним не требуется.

Подготовка выполняется автоматически в целевом сценарии ORTO. Это не отдельная операция, которую оператор должен каждый раз вручную повторять.

### Настройки ORTO

Специализированные параметры подготовки находятся в отдельной вкладке **Preferences → ORTO**:

- **Подъём модели над столом** — задаёт высоту нижней точки модели относительно плоскости стола. Значение по умолчанию: **3 мм**.
- **Положение Support Blocker** — задаёт высоту нижней плоскости штатного модификатора Support Blocker над столом. Значение по умолчанию: **20 мм**. Верхняя плоскость блокера автоматически располагается на 20 мм выше верхней точки оболочки.

Оба параметра независимы друг от друга, доступны для изменения оператором и сохраняются в настройках OrcaSlicer. При последующей подготовке используются сохранённые значения; 3 мм и 20 мм являются значениями по умолчанию, а не жёстко заданными величинами.

## Интеграция с ORTO

Целевой производственный сценарий:

1. ORTO запускает `orto-orca-slicer.exe` с параметром `--nogui`.
2. Передаются JSON-файлы профилей принтера, процесса и филамента и путь к STL-модели.
3. OrcaSlicer загружает профили и модель штатным CLI-механизмом.
4. Выполняется ORTO-подготовка: поворот, подъём, Precise Seam Modifier и Support Blocker.
5. Штатный CLI-движок выполняет нарезку и экспортирует G-code в `--outputdir` под именем исходной модели (например, `cover3.gcode`).
6. Процесс завершается с кодом успеха или ошибки.

Для интерактивной работы используется `--gui`. Без явного параметра сохраняется прежнее поведение GUI.

**Важно:** `--nogui` использует тот же геометрический алгоритм ORTO-подготовки и штатный движок OrcaSlicer. Для headless-сценария на текущем этапе поддерживается одна STL-модель с одним объектом и одним экземпляром. Значения подъёма модели и положения Support Blocker читаются из сохранённых настроек ORTO; значения по умолчанию — 3 и 20 мм. Для `--nogui` каталог данных определяется так же, как в GUI: сначала `data_dir` рядом с Portable-сборкой, затем пользовательский каталог приложения. При первом headless-запуске недостающие системные профили устанавливаются из каталога `resources/profiles`. Внешние пользовательские JSON-профили (`from: "User"`) могут находиться в произвольной папке: если профиль содержит `inherits`, CLI находит родительский системный профиль по имени в загруженном bundle и применяет поверх него настройки внешнего JSON. Предварительный импорт такого пользовательского профиля в каталог OrcaSlicer или запуск GUI не требуются.

### Передача профилей через командную строку

Для загрузки пользовательских профилей используются штатные параметры OrcaSlicer:

- `--load-settings` — профили принтера и процесса;
- `--load-filaments` — профиль или профили филамента.

Пример автоматического запуска с нарезкой и сохранением G-code:

```bat
orto-orca-slicer.exe --nogui ^
  --load-settings "D:\orto-orca\profiles\elegoo4max_printer.json;D:\orto-orca\profiles\elegoo4max_process.json" ^
  --load-filaments "D:\orto-orca\profiles\elegoo4max_filament.json" ^
  --outputdir "D:\orto-orca\gcode" ^
  "C:\temp\cover3.stl"
```

В `--nogui` параметр `--slice 0` добавляется автоматически, если он не указан явно. `--outputdir` обязателен: каталог создаётся автоматически, а G-code получает имя исходной STL-модели. Для обычного GUI-запуска:

```bat
orto-orca-slicer.exe --gui --load-settings "profiles\printer.json;profiles\process.json" --load-filaments "profiles\filament.json" "model.stl"
```

В примере используются абсолютные пути. ORTO должна передавать корректные пути к файлам профилей и модели. JSON-файлы должны содержать корректные определения профилей OrcaSlicer соответствующих типов и необходимые настройки.

Загрузка пользовательских JSON-профилей использует штатную систему пресетов OrcaSlicer. Сопутствующие файлы метаданных пресетов не являются заменой исходным JSON-файлам.

## Windows Portable

Для производственного рабочего места используется отдельная Portable-сборка ORTO OrcaSlicer. Это единственный поддерживаемый формат распространения ORTO Edition; инсталлятор не собирается и не публикуется.

Рекомендуемый принцип развёртывания:

1. Распаковать Portable-сборку в отдельный каталог.
2. Не смешивать её с обычной установкой OrcaSlicer.
3. Настроить в ORTO путь к `orto-orca-slicer.exe`.
4. Запускать слайсер из ORTO с необходимыми аргументами и путями к профилям.

Такой способ позволяет использовать специализированную сборку ORTO независимо от пользовательской установки OrcaSlicer.

**ORTO Quick Build** — ускоренная инкрементальная Windows-сборка, создающая только Portable-артефакт.

**ORTO Windows Portable Build** — основной workflow для сборки Windows Portable. Он использует проверенный Quick Build и не запускает upstream-процедуру упаковки установщика.

Публикация GitHub Release выполняется отдельным workflow после успешной сборки Portable. В релиз загружается только Windows x64 Portable ZIP; версия тега обязана совпадать с `version.inc`.

### Правила разработки

- ORTO-функциональность разрабатывается в ветке `orto-dev`.
- Не отправляйте изменения форка непосредственно в upstream OrcaSlicer.
- При доработках по возможности используйте существующие механизмы OrcaSlicer: загрузку профилей, работу со сценой, модификаторы и экспорт.
- Не дублируйте штатную функциональность без необходимости.
- Сохраняйте совместимость с производственным сценарием запуска из ORTO.
