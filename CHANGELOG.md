# Changelog — ORTO OrcaSlicer

## 2.6.0-ORTO.19 TEST — IN PROGRESS

- Добавлен явный производственный контекст запуска `--orto-mode production`, отделённый от технологического алгоритма `--orto-algorithm cosmetic_shell`.
- Добавлены параметры контекста заявки, позиции/физической единицы, принтера, уникального задания и локального каталога подтверждённого результата.
- Автоматическая подготовка Cosmetic Shell, соответствующая команда контекстного меню и вкладка ORTO в настройках ограничены явным производственным контекстом.
- Добавлена производственная кнопка «Подтвердить G-code», копирование текущего G-code в локальный каталог, SHA-256 и sidecar JSON-манифест; после успешного подтверждения приложение закрывается.
- Обычный запуск без ORTO Mode сохраняет штатный сценарий OrcaSlicer и не показывает производственные элементы интерфейса.
- Производственный запуск требует интерактивный GUI, одну STL-модель и полный комплект из двух JSON в `--load-settings` (printer/process) и одного JSON в `--load-filaments`; автоматический headless-слайсинг в production approval session отклоняется.
- Сборочная и функциональная проверка .19 ещё не завершена. Предыдущая проверенная версия — 2.6.0-ORTO.18 RELEASE.

## 2.6.0-ORTO.18 RELEASE — VERIFIED

- Исправлено разрешение `inherits` для внешних пользовательских JSON-профилей в headless CLI (`--load-settings` и `--load-filaments`): если профиль не найден в bundle по исходному пути, его настройки накладываются на загруженный родительский системный профиль. Поведение согласовано с загрузчиком профилей GUI.
- Добавлен end-to-end CLI-тест загрузки внешних пользовательских профилей принтера, процесса и филамента с наследованием системных настроек.
- Проверена Windows x64 Portable-сборка GitHub Actions #75 из коммита `c7b4ee5`.
- Подтверждён целевой headless-сценарий: CLI загрузил внешние JSON-профили принтера, процесса и филамента, выполнил слайсинг и создал G-code; G-code открыт и проверен вручную.
- Подтверждена штатная работа GUI с профилями. CLI без явно переданных профилей не относится к целевому сценарию интеграции ORTO и не входит в критерии приёмки этой версии.

## 2.6.0-ORTO.17 TEST

- Исправлена инициализация каталога данных при запуске `--nogui`: используется Portable `data_dir`, если он существует, иначе штатный пользовательский каталог приложения; явный `--datadir` сохраняет приоритет.
- При первом headless-запуске устанавливаются только отсутствующие системные vendor-профили из `resources/profiles`. Уже установленные системные профили не перезаписываются.
- При первом headless-запуске подготавливается системный preset bundle, необходимый для последующего разрешения `inherits` у внешних пользовательских профилей без предварительного запуска GUI.
- Обновлена документация по headless-загрузке профилей.

## 2.6.0-ORTO.16 TEST

- Добавлен режим автоматической подготовки и нарезки косметической оболочки через `--nogui`.
- Добавлена подготовка Precise Seam Modifier и Support Blocker без запуска графического интерфейса.
- Добавлена обязательная передача `--outputdir` и автоматическое формирование имени G-code по имени исходной STL-модели.
